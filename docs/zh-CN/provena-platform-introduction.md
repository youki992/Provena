# 安全测试不该在十个窗口之间来回切换，Provena 想把工作收回到一个地方

做过安全测试的人，大概都见过这样的桌面。

浏览器里开着资产测绘，终端里跑着信息收集工具，Burp 或 Yakit 里堆着一串请求，表格里记着资产和漏洞，聊天窗口又在问 AI 下一步该做什么。事情并没有少做，只是上下文被拆得很碎。过几个小时再回头看，常常要花很久才能回答三个简单的问题，测了什么、发现了什么、下一步为什么这么做。

Provena 是为这种场景做的本地安全工作台。它把对话式协作、资产与漏洞管理、抓包分析、本地工具、MCP 工具接入和过程留痕放在同一个界面里，让授权范围内的安全工作可以连续地推进，也可以随时回看。

## 先把目标说清楚，再让 Pi Agent 帮你推进

Provena 当前将对话执行统一交给 Pi Agent。用户可以直接在对话框描述已获授权的测试目标、现状和要求，例如「整理这个已授权域名的资产信息，优先关注暴露的管理端和高风险服务」。

Pi Agent 不只是给出一段建议文本。它会结合已经接入的平台工具、当前会话上下文和可用的知识资料，帮助把任务拆成可以执行、可以复核的步骤。对话里的过程、工具调用和结果都留在同一个工作区，后续交接或复盘时不必重新拼接聊天记录和终端输出。

对于团队来说，这种方式有一个很实际的好处。新人不需要先记住每个工具的完整命令，经验丰富的测试人员也不用反复解释「这一步为什么要做」。大家先把目标、范围和限制讲明白，再让平台把工作流推进下去。

## 抓到的请求，不再只躺在代理历史里

抓包通常是测试里信息密度最高的一段。

一个登录请求、一段接口响应、一个异常参数，里面可能同时有业务路径、鉴权方式和后端行为。但代理历史一多，真正有价值的请求很容易被埋住。复制粘贴给模型又容易漏字段、漏上下文，还可能把无关内容一并带进去。

Provena 内置抓包代理和抓包分组能力。平台可以按请求特征归纳流量分组，测试人员在对话输入区点击「抓包」按钮后，用主机、路径、分组名或指纹进行模糊搜索，再选择需要交给 Pi Agent 分析的分组。

当筛选结果很多时，可以直接使用「全选当前筛选」。已经选中的其他分组不会因为变更搜索条件而丢失。选择数量会显示在按钮角标上，输入框本身也不会被分组列表挤占。

![抓包分组选择与搜索](../../images/provena-packet-picker-placeholder.png)

*图中建议替换为抓包分组弹层截图，突出搜索框、全选当前筛选、已选数量和请求列表。*

这一步的价值不在于「把所有包都扔给 AI」。更好的做法是只选择与当前任务有关的分组，让模型拿到完整而克制的证据。上下文更干净，分析也更容易落到具体接口和具体行为上。

## 从资产到漏洞，信息不再各自为政

资产管理和漏洞管理往往是两个独立系统，测试记录又在第三个地方。Provena 把这些信息放进同一个工作台。

资产侧可以统一归档域名、IP、端口和服务，支持导入导出、筛选、去重、批量维护和风险状态跟踪。漏洞侧提供分级、状态流转、筛选和统计视图。对话中的分析结果也可以继续沉淀到后续管理动作里，而不是停留在一段临时的聊天回复中。

你可以把它理解成一条更顺手的工作线。

```text
已授权目标 → 资产梳理 → 抓包取证 → Pi Agent 协作分析 → 漏洞归档 → 复盘与交接
```

每一环都不必强行自动化。平台更看重的是把证据、判断和动作关联起来，让测试人员在关键节点保持判断权。

## 工具可以接进来，过程也要看得见

安全工作不会只依赖一种工具。

Provena 支持本地工具执行，也支持通过 MCP 接入 HTTP、stdio、SSE 等类型的工具服务和外部能力。工具多了以后，真正麻烦的是执行过程变得不可见，长任务卡在哪里、某个服务为什么连续失败、结果有没有被截断，往往比「能不能调用」更重要。

平台提供 MCP 管理和状态监控，围绕工具调用保留执行记录，并支持并发控制、失败熔断、等待与取消等机制。这样做不是为了让页面看起来复杂，而是为了让人能在任务运行时看得见状态，在结果回来后找得到依据。

对于已有工具链的团队，这意味着不必把所有脚本推倒重来。可以先把常用能力接入，再逐步把流程和记录收进 Provena。

## 方便不等于放开边界

安全测试工具的效率越高，边界越应该写得清楚。

Provena 面向自有资产或已经取得明确授权的测试任务。平台可以通过人机协同审批、工具白名单和执行记录，把需要人工确认的动作从自动流程中拎出来。测试人员可以让 Pi Agent 提供分析和推进建议，但范围、风险和最终执行决策仍然由人负责。

这不是额外的负担。对于团队协作、客户项目和长期运营来说，能解释「谁在什么范围内做了什么」本身就是交付的一部分。

## 解压、配置、开始工作

Windows 发布包名为 Provena，包含服务端、Web 界面，以及便携 Node.js 和 Pi Agent 运行时。普通使用者解压后运行 `START.bat`，首次启动会创建本地配置和数据目录。

接下来只需完成三件事。

1. 在系统设置中配置自己的 AI 通道、Base URL、模型和 API Key。
2. 根据项目需要接入本地工具、MCP 服务或抓包代理。
3. 新建对话，说明已授权的目标、范围和预期结果。

平台启动不依赖本机 Go 环境。Pi Agent 已随标准 Windows 发布包提供，正常使用不需要再单独安装 Node.js 或 Pi。

Provena 不会替代安全人员的经验。它做的是把原本散落在浏览器、终端、代理工具和表格里的工作，收敛成一条看得清、接得上、留得住的路径。

如果你下周一要开始一个新的授权项目，可以先不急着把所有工具都搬进来。选一个真实目标，接入一项常用工具，抓一组关键请求，然后在对话里把问题讲清楚。剩下的流程，交给 Provena 和 Pi Agent 一起往前推。
