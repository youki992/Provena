# 安全加固指南

[English](../en-US/security-hardening.md)

本文给出 Provena 上线前和持续运行中的安全加固清单。

## 上线前必做

- 首次部署后立即修改 `admin` 初始密码（Web 界面或平台权限 → 用户管理）。
- `config.yaml` 只让自己可读，里面是模型凭证。
- 限制来源 IP、VPN 或堡垒机访问。
- 开启 `audit.enabled`。
- 不要提交 `config.yaml`、`data/`、`tools/bin/`。
- 不暴露独立 HTTP MCP，除非设置强认证和网络隔离。
- 外部 MCP 只接可信服务。
- 备份 `config.yaml`、`data/`、自定义资源目录。

## HITL 白名单基线

推荐最小白名单：

```yaml
hitl:
  tool_whitelist:
    - read_file
    - glob
    - grep
    - tool_search
```

不要默认加入：

- `execute`
- 外部 MCP 高风险工具
- 删除、写入、上传、持久化相关工具

## 文件权限

建议：

```bash
chmod 600 config.yaml
chmod 700 data
```

生产环境使用独立系统用户运行：

```text
provena:provena
```

避免 root 运行，除非明确需要绑定低端口或访问特殊资源。

## 外部 MCP 审查

接入前确认：

- 工具是否能执行命令。
- 是否能读写本机文件。
- 是否会把数据发往第三方。
- 是否有自己的认证。
- 是否会返回不可信网页或模型内容。
- 是否需要容器隔离。

接入后：

- 高风险工具不进白名单。
- 定期检查工具列表变化。
- 审计配置变更。

## 数据保留

建议：

- 审计：30-90 天。
- 工具监控：90-180 天。
- 上传附件：项目结束清理。
- 工具输出：只保留报告需要的证据。
- 知识库：不放真实凭证和客户私密数据。

## 周期巡检

每周：

- 登录失败和异常 IP。
- 配置变更。
- 外部 MCP 增删改。
- 长时间运行工具。
- 磁盘空间和数据库大小。

每个项目结束：

- 清理临时 workspace。
- 删除无用附件。
- 归档必要证据。
- 删除过期报告和临时工作区。
- 导出审计记录。
